# 🔐 Caesar Cipher Security Lab

An interactive **educational cryptography and security lab** built with Python, Streamlit, and SQLite. Explore classical encryption, decryption, brute-force attacks, frequency analysis, input validation, and audit logging.

> **Security warning:** Caesar Cipher has only 26 effective keys. It is not secure encryption and must never be used to protect passwords, personal data, or confidential information.

## What you can explore

- **Cipher console:** encrypt and decrypt alphabetic text with a chosen key.
- **Character mapping:** inspect how each letter shifts.
- **Brute-force lab:** enumerate all 26 possible shifts.
- **Frequency analysis:** inspect alphabetic counts and percentages.
- **Round-trip verification:** check whether decryption recovers the original text.
- **Security analysis:** see the tiny key space and practical limitations.
- **Local operation history:** explore SQLite-backed records generated by the lab.
- **Automated tests:** run regression checks for cipher logic, analysis, validation, and database behavior.

## Cryptographic model

Letters are mapped to integers from 0 to 25. For key (k):

`Encryption: C = (P + k) mod 26`

`Decryption: P = (C - k) mod 26`

Example with key 3:

| Operation | Text |
|---|---|
| Plaintext | `HELLO` |
| Encrypt with key 3 | `KHOOR` |
| Decrypt with key 3 | `HELLO` |

Keys are normalized modulo 26, so keys 3 and 29 produce the same transformation. The implementation preserves letter case and leaves spaces, punctuation, and digits unchanged.

## Installation

Requirements: Python 3.11 or 3.12 recommended.

```bash
git clone https://github.com/Atharva-ark06/CAESAR-CIPHER-SECURITY-LAB.git
cd CAESAR-CIPHER-SECURITY-LAB
python -m venv .venv
```

Activate the virtual environment:

**Windows PowerShell**
```powershell
.venv\Scripts\Activate.ps1
```

**macOS / Linux**
```bash
source .venv/bin/activate
```

Install dependencies and run the app:

```bash
python -m pip install -r requirements.txt
streamlit run app.py
```

## Run the tests

Install development tools and execute the test suite from the repository root:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest
```

GitHub Actions is configured to run the tests on Python 3.11 and 3.12 for pushes and pull requests targeting `master`.

Run an individual learning example with:

```bash
python examples/brute_force_walkthrough.py
python examples/frequency_walkthrough.py
python examples/round_trip_walkthrough.py
python examples/validation_walkthrough.py
python examples/key_space_walkthrough.py
```

## Security and privacy notes

- The brute-force lab demonstrates why a 26-key cipher is trivial to search.
- Frequency analysis is heuristic and can be unreliable on short or unusual text.
- The local SQLite history currently records operation messages and results. **Use synthetic examples only**; do not enter secrets or personal information.
- SQLite history is a local teaching feature, not a tamper-evident audit system.
- Input validation and automated tests improve software quality but do not make this cipher cryptographically secure.
- Read the additional notes in `docs/` for the threat model, audit-log privacy, testing strategy, limitations, and lab exercises.

## Learning outcomes

This project supports practice with classical cryptography, modular arithmetic, cryptanalysis, Python modules, automated testing, validation, SQLite, and security-focused documentation. It is intended for classroom learning and demonstration—not real-world protection.
